# 阶段五：故障排查

## 管理页打不开

1. 从开始菜单运行“启动物流运价系统”。启动入口会等待健康接口，不再固定等待5秒。
2. 若90秒后页面仍未打开，检查是否有旧版程序占用配置中的管理端口。
3. 查看 `data\logs\freight-supervisor.log` 和 `data\logs\freight-live.log`。
4. 若安装时启用了自动启动，请在任务计划程序中确认 `FreightRateStatisticsSystemAutoStart` 存在。

管理端口修改后，开始菜单和桌面快捷方式会读取配置并使用新地址。采集器曾正常运行、之后进程仍在但接口连续90秒无响应时，监督器只会定向重启本项目的采集子进程。

## 状态为 setup_required

系统尚未配置QQ群。进入“群与线路管理”，至少保留一个始发地、一个目的地和一个纯数字群号，保存后等待自动重启。

## 状态为 disconnected

- 确认NapCat和QQ正在运行并已完成扫码。
- 确认普通QQ没有抢占同一账号。
- 确认NapCat WebSocket服务器监听 `127.0.0.1:3001`。
- 确认两边Token完全一致。
- Windows命令可检查端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 3001
```

## 群消息没有进入统计

- 群号必须在管理页白名单内，NapCat登录QQ也必须已经加入该群。
- 目的地、货物和价格必须都能识别。
- 价格超过配置上限不会进入均价。
- “求车、找车、有车了”等无效关键词会被过滤。
- 查看该群的 `未识别消息.csv` 获取具体原因。

## 明天或后天报价出现在今天

查看原消息是否包含可识别日期词，并检查 `待生效运价.csv`。系统只允许未来日期进入缓存，到期后才自动转正；系统可信时间显示在状态页。

## 重复报价仍然出现

查重键包含生效日期、标准始发地、具体目的地、货物种类和全部价格。任一项不同都视为不同报价；发布人不参与查重。若只是写法不同，请为地区增加统一别名。

## 图片没有识别

- Windows需要安装“简体中文”OCR语言能力。
- 图片应清晰、文字方向正常、分辨率足够。
- OCR失败消息会进入 `未识别消息.csv`，原图来源仍可审计。
- 先用相同内容发送纯文字，判断是OCR还是业务规则问题。

## Excel没有立即更新

关闭正在打开的 `物流报价汇总.xlsx`。程序不能覆盖被Excel锁定的文件，会先写入 `物流报价汇总_待更新.xlsx`，下次成功更新时自动替换。

## 系统时间不同步

程序先尝试Windows时间服务，再从HTTPS响应头计算内部可信时间。即使没有权限修改系统时钟，未来缓存仍使用可信时间判断。若偏差异常，检查网络、防火墙和Windows时间服务。

仍无法解决时，在GitHub提交Issue，并附上已脱敏的日志、状态页错误、Windows版本和复现消息；不要上传Token、QQ号、群号、聊天数据库或真实客户报价。
