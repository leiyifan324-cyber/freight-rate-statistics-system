# 数据与统计规则

## 信息提取

每条有效报价至少需要目的地和价格；货物未写时使用配置的默认小类（初始为“大板”），始发地未写时使用QQ群默认值。地区别名归入标准城市，但“具体目的地”仍保留区县信息，例如“佛山南海”和“佛山顺德”是不同明细线路。

货物先按全局最长别名识别为标准小类，再按配置归入大类。小类用于明细和内容查重，大类用于日/周/月/年汇总。管理员可以给某一小类或大类配置允许线路白名单；小类专属规则优先于大类规则。没有规则的货物允许全部现有线路，某货物被限制时不会影响其他货物；越界消息进入“不合格”并保留明确原因。

价格列表支持单价和多价格写法，最终输出统一保留三位小数。

## 日期与未来缓存

- 今天、今日、今晚：当天正式数据。
- 明天、明日、明早、明晚：下一天缓存。
- 后天：第二天缓存。
- 今明两天：拆为今天和明天两条生效记录。
- 明后天：拆为明天和后天两条缓存。
- 支持 `8月15日`、`2026年8月15日`、`8/15`、本周/下周星期表达。

缓存只接受严格晚于可信今天的日期。日期到达后自动转为正式数据并从缓存输出中消失；过去日期不会进入未来缓存。

## 查重

正式数据和未来缓存共同使用内容查重。查重键为：

`生效日期 + 标准始发地 + 具体目的地 + 货物种类 + 完整价格集合`

发布人和消息ID不参与内容查重，因此同一天不同人转发同一报价只统计一次。日期、地点、货物或任一价格不同则保留为不同数据。

## 日统计

每天按标准始发地、目的城市和货物大类分别汇总平均、最低、最高价格及报价数。不同大类即使日期和线路相同也不会混算。日均数据保留在CSV和Excel中，不生成日价格走势图。

## 周统计

每个春节年度从春节当天重新计周，每7个自然日为一周。完整7天后形成周数据；周平均是周期内实际有数据日期的日均价算术平均，同时记录观察天数、数据天数和覆盖率。

## 月统计

按自然月处理28、29、30、31天和闰年2月。春节所在首月从春节当天开始，下一年春节所在末月到春节前一天结束；不足整月也作为该春节年度的月数据。月平均以实际有数据日期的日均价计算，并标记进行中或完整。

## 年统计

一个春节年度从当年农历正月初一开始，到下一年春节前一天结束，以起始春节的公历年份命名。春节日期由农历转换计算，不写死。年度走势图以自然月为基本单位，年平均对已有月平均价等权计算；到下一年春节后标记完整，未到边界时保留进行中数据和月份覆盖率。

如果春节期间系统没有运行，新年度首次启动会在连接NapCat接收新消息前，先从SQLite补齐所有已结束春节年度的大类和小类归档，再生成当前春节年度文件。归档使用数据摘要判断是否需要重建，重复启动不会反复改写未变化的旧归档；迟到的旧年度记录会触发对应归档更新。

## 输出和数据源

- SQLite `运价数据.db`：正式增量数据源。
- `报价明细.csv`、`待生效运价.csv`、`每日平均运价.csv`。
- `每周平均运价.csv`、`每月平均运价.csv`、`每年平均运价.csv`。
- `物流报价汇总.xlsx`：报价、缓存、历史每日平均运价和全部周期工作表；历史日均价不再重复生成独立CSV。
- `charts`：按线路和货物大类分别生成周、月、年走势图。
- `未识别消息.csv`：提取失败原因及原始消息审计。
- `年度归档/<年份>春节年度/大类统计/`：旧春节年度的大类明细、日/周/月/年统计、汇总Excel及图表。
- `小类统计/<大类>/<小类>/年度归档/<年份>春节年度/`：旧春节年度的小类每日Excel及周/月/年图。

当前目录中的大类和小类业务文件只呈现当前春节年度；SQLite `运价数据.db`继续保存全量历史。归档不删除数据库原始记录。

没有报价的日期不会人为补造价格；覆盖率字段用于判断样本完整度。
