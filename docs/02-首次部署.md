# 阶段二：首次部署与验收

## 第一步：登录 NapCatQQ

1. 确认已经自行安装官方64位QQ；Release不包含QQ。
2. 完全退出普通QQ，包括系统托盘中的QQ图标。
3. 从开始菜单运行“安装或更新NapCatQQ”（首次尚未安装时），然后运行 `安装目录\NapCatQQ\Start-NapCat.cmd`。旧安装请以实际保存路径为准。
4. 使用手机QQ扫描控制台二维码并完成授权。
5. 保持NapCat和QQ运行，不要关闭其控制台窗口。

建议使用已经加入报价群的专用QQ账号。

## 第二步：配置 OneBot WebSocket

1. 打开 NapCat WebUI。地址和WebUI登录Token会显示在NapCat启动日志中。
2. 进入“网络配置”。
3. 新建或启用 OneBot 11 的 WebSocket服务器：
   - 主机：`127.0.0.1`
   - 端口：`3001`
   - Token：建议生成随机Token；若设置，稍后必须在物流系统中填写相同值。
   - 上报自身消息：如果需要统计采集QQ自己发送的报价，请启用。
4. 保存配置并确认端口已经启动。

不要把主机设置成 `0.0.0.0`，也不要把端口映射到公网。

## 第三步：打开系统管理页

从开始菜单打开“启动物流运价系统”。启动入口会等待本机健康接口就绪；首次没有群配置时自动打开“群与线路管理”，配置完成后再次启动则直接打开实时状态页。也可以直接打开开始菜单中的“群与线路管理”。

默认地址为：

`http://127.0.0.1:8765/?view=config`

首次未配置群时，运行状态显示 `setup_required` 属于正常现象。

## 第四步：填写连接、群和线路

依次完成：

1. 填写 OneBot WebSocket地址和相同的Access Token；新安装的NapCat启动器使用安装目录内 `NapCatQQ\Start-NapCat.cmd`。WebUI登录Token不等于OneBot访问Token。
2. 检查始发地范围；新增始发地时同时填写常见市、区、县、镇别名。
3. 检查目的地范围；每个新增标准目的地会与全部始发地自动形成可统计线路。
4. 添加QQ群号、群名称，并选择未写始发地时使用的默认始发地。
5. 检查货物种类和价格上限。
6. 点击“保存并自动应用”，等待约15～30秒。
7. 需要手动年度时，到“年度归档”填写年度名称和开始日期并确认启用；新安装不带旧年度或旧数据。顶部若显示“已停止采集”，点击“开始采集”。连接在线与采集已开始是两个不同状态。

以上系统配置只需首次填写。以后依次完成NapCat扫码登录和NapCat WebUI启动OneBot服务，再打开“启动物流运价系统”，系统会自动使用已保存配置连接、接收、分类、写入并刷新页面。

字段含义和高级选项统一见 [配置参考](06-配置参考.md)，此处不重复列举。

## 第五步：部署验收

等待运行状态变为 `connected`，然后在测试群依次发送：

```text
佛山南海 大板 120
明天杭州余杭 红板 180
后天成都双流 拼板 210
```

再让另一名成员重复发送第一条文字。验收结果应为：

- 第一条进入当天正式数据。
- 明天和后天数据进入“待生效运价”，不会计入今天。
- 重复报价只保留一条。
- 默认仅处理文字，图片直接跳过。有歧义的文字在“不合格消息”中查看原因；按方报价不采集。
- 不同群分别在 `data\QQ群_群号` 下生成独立结果；群名称只用于页面显示，改名不会切换历史目录。
- “数据与报表→Excel/CSV/图表”能下载实际文件；手动年度模式当前文件为 `手动年度统计/当前/年度统计汇总.xlsx`。遗留春节模式文件名不同，不要混用。

若结果不符，按 [故障排查](05-故障排查.md) 检查。验收通过后进入 [正常使用](03-正常使用.md)。
