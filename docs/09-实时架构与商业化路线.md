# 实时架构与商业化路线

## 当前数据路径

```text
QQ群消息
  → NapCat OneBot WebSocket
  → WebSocket接收循环（只接收和分发）
  → 每群SQLite持久收件箱（先落盘）
  → 按QQ群独立的串行处理线程
  → 文本/OCR解析与规则判断
  → 各群独立SQLite数据库
     ├─ 页面实时查询：正式识别 / 待生效 / 不合格
     ├─ 每群生命周期维护：去重 / 不合格 / 死信 / 正式历史 / 备份
     └─ 每群Excel更新工作线程
          ├─ 批量追加报价明细或待生效记录
          └─ 低频全量校准日、周、月、年汇总与图表
```

## 为什么采用两层处理

- WebSocket线程只等待很短的SQLite持久化，不等待解析或Excel；持久化成功的待处理事件在异常重启后会自动重放。
- 每个群独立排队和串行入库，同一群保持消息顺序，不同群可同时解析；内存队列仅保存容量为1的唤醒信号，不随积压量增长。
- SQLite使用WAL模式，每个群数据库和输出目录完全分离。
- 群输出目录以群号稳定定位为 `QQ群_<群号>`；单个旧版“群名_群号”目录会自动迁移，群改名不影响历史数据。
- Excel普通增量追加按群并行，同群严格串行；旧全量统计流程使用进程级工作目录，因此全量构建仍通过全局锁串行，避免串目录。
- 连续消息先合并，再打开Excel一次；明细优先追加，汇总按配置的较低频率校准。

## 页面可观测信息

- WebSocket连接状态、最近链路事件、最近心跳、重连次数和最后错误。
- 每个群的正式、待生效、不合格数量。
- 每个群的队列状态、积压数量、累计接收和处理数量。
- 持久队列标识、死信数量和排空超时状态。
- Excel更新状态、追加/全量模式、汇总是否待刷新。
- 生命周期策略来源（默认模板/群专属）、运行状态、最近维护时间、本次和累计清理数量。
- 最近消息处理明细，包括群、分类、接收时间、生效日期、发布人、线路、货物、价格及拒绝原因。

页面默认每2秒刷新；页面读取内存状态和SQLite，不等待Excel完成。

## Excel一致性策略

1. SQLite是唯一事实数据源，Excel是可交付报表，不承担消息队列或主存储职责。
2. 新记录先写SQLite，再批量追加到“报价明细”或“待生效运价”工作表。
3. 追加前按日期、发布人、线路、货物、报价和原文去重，避免与正在完成的全量刷新重叠。
4. 日、周、月、年统计及图表按 `excel_full_refresh_seconds` 定期校准，跨日强制校准。
5. Excel被占用时写入“物流报价汇总_待更新.xlsx”，下次更新自动尝试替换。
6. 默认启动时执行全量校准，可修复上次异常退出造成的Excel滞后。

## 已验证项目

- 普通消息与 `message_sent` 自身消息接收。
- 多群独立队列、快群不被慢群阻塞、每群顺序处理。
- Excel按群隔离、同群请求合并、增量追加、全量安全串行和交界去重。
- 正式、待生效、不合格三类页面和API反馈。
- 管理页新增群、始发地、目的地，修改群名、价格及运行参数，保存、备份、回读和重启反馈。
- 配置应用采用“停止接收—排空群队列—排空Excel队列—同进程重载”，直接启动时也不依赖监督程序恢复。
- 真实WebSocket握手、连接中断、自动重连、重连前后消息处理和空闲心跳。
- 持久收件箱异常重放、内存有界、排空超时阻止新旧会话重叠。
- 双配置文件硬中断恢复、配置版本冲突、Token脱敏、Host/Origin/CSRF校验和严格端口/URL校验。
- 生命周期默认模板、新增群自动继承、群专属覆盖、独立间隔调度、分表保留、0永久保留、未来运价与待处理队列保护、备份轮转，以及正式数据清理后的Excel和历史汇总校准。

## 距离商业生产仍需补齐

当前版本已经具备可靠的单机基础架构，但在正式商业部署前仍建议完成：

1. **管理角色与审计**：当前页面严格限定本机并具备CSRF与版本保护；多用户或远程管理仍需正式身份认证、角色、操作审计和二次确认。
2. **告警体系**：增加持久队列积压/死信、连续解析失败、Excel长期未刷新、NapCat反复重连的桌面或企业微信告警。
3. **数据治理制度**：系统已具备可配置保留和自动清理能力；商业部署仍需明确聊天原文期限、脱敏、访问权限、审批与删除审计制度。
4. **灾难恢复演练**：定期验证数据库备份、配置备份和Excel恢复，而不仅是生成备份文件。
5. **实际NapCat长稳测试**：在真实QQ账号、真实群流量下运行至少72小时，记录延迟、重连、内存和磁盘增长。
6. **大规模容量测试**：用百万级历史记录和多群突发消息验证磁盘、SQLite、页面查询及Excel投影的上限。
7. **发布验收**：重新打包安装版，在独立测试机验证开机自启、监督重启、升级回滚和卸载。

在完成以上项目并形成验收记录前，不应把当前版本宣称为无人值守的商业生产最终版。
